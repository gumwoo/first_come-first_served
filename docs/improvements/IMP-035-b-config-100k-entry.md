## 1. 상황 (Context)
README의 "10만 명 / 10초 진입" 수치는 [[IMP-031]] 기준이었다. 그때는 Kafka가 있었고 api 하나가 진입·폴링·예매를 함께 받는 A′ 구성이었다(진입을 api 9개가 받음).
그 뒤 두 가지가 바뀌었다.
- Kafka를 앱에서 뺐다([[ADR-028]]).
- 대기열 전용 Deployment(B)를 운영 기본값으로 정했다([[ADR-027]], #434). 평시에는 api 3 + 대기열 2로 돌고, 오픈 전에 Git PR로 대기열만 6으로 늘린다.

진입을 받는 파드가 api 9개에서 대기열 6개로 바뀌었으므로, 같은 기준으로 다시 재야 README 수치를 B 구성에 붙일 수 있다.

## 2. 문제 정의 + 분류
운영 기본값인 B 구성(오픈 전 대기열 6)이 공연 오픈 10초 동안 10만 명 진입을 받으면서 정원 초과·정합성 위반 없이 대기 상태를 전달하는가.
- 계층: 네트워크(ALB 도착)·애플리케이션(대기열 진입·상태 조회)·동시성(입장 정원)·자동 확장(Git 사전 확장 → HPA·CA 인계).

- 세션 중 결정(`session.log`에 시각과 함께 기록):
  - 전체 워밍업 run은 따로 하지 않고 run 안의 예열 단계만 두었다.
  - 공연 상세 데이터 시딩은 4/10회차에서 멈췄다(진입 시험에 불필요, 3분 주기 관리자 동기화가 판정 run과 겹치지 않게).

## 5. 판정 도구 종료 코드 2의 원인과 판정 구간
`check-correctness`는 rc=2로 끝났다. 위반 검사는 모두 0이었고, rc=2는 실시간 감시기 조회 오류 11틱 때문이다.
- 오류 시각: 10:02:00~10:02:50Z. 판정 구간(since ~ until + 30초 = 10:01:43Z)이 끝난 뒤, 감시기가 종료되기 전 구간이다.
- 원인(로그로 확인):
  1. 끄기 PR 뒤 대기열이 줄었다.
  2. CA가 노드 `ip-10-0-118-246`을 비웠다(`ca.log`: 10:01:52Z "Scale-down: removing node"(옮길 파드에 Prometheus·coredns 포함) → 10:03:03Z "All pods removed").
  3. 그 노드에 있던 Prometheus 파드(1개)가 옮겨지는 동안 감시기 조회가 `fetch failed`로 실패했다.
- 판정 구간 안 216틱은 조회 오류가 없고 위반 0이다. oversold·tick 실패·신선도는 모든 틱에 값이 있다. over-admit·카운터 어긋남은 대기열에 아무도 없던 T0 전 30틱(감시기 시작부터 세면 37틱)에 시리즈가 없고, 이후 값은 0이다.
  - 감시기 시작부터 보면 오류 없는 틱은 226개다(09:43:08~10:01:55Z). 사후 재확인 109점도 위반 0이다.
  - 판정 기준: 사전 등록한 판정 구간 안의 틱으로 Correctness·Protection을 판정했다. 원인과 판정 근거는 `session.log`에 시각과 함께 남겼다.
- 같은 drain으로 coredns 1개도 옮겨졌다. 다른 1개는 다른 노드에 있었다(#431 분산).

## 8. 트레이드오프 / 다음 개선
- 측정 조건: 판정 run 1회 관측(사용자 결정). 폴링 폭증·예매 묶음은 함께 돌리지 않았다. B의 폴링 폭증 확장과 그때의 예매 지연은 [[IMP-033]]·[[IMP-034]]의 결과(각 2회, 대기 인구 6만 기준)다.
- 발생기는 진입·상태 조회 API를 바로 부른다. 이벤트 페이지 진입 시 브라우저가 web을 거쳐 api를 부르는 부하(새로고침·포커스 재요청)는 시험 범위 밖이다.
  - 대기열 화면 쪽 web 부하는 #436(정적 경로·prefetch)에서 줄였고, 10만 규모 클러스터 측정은 다음 과제다.
- 노드 축소: 폴링이 끝나고(T0 + 900초) 노드 9 → 7까지 약 8분 더 걸렸다(CA 축소 대기, 실측). 노드-시간 영향은 [[IMP-032]]의 계산 방식으로 따로 계산한다.
- 실시간 감시기는 Prometheus 단일 파드에 의존해, CA drain 같은 정상 운영 이벤트 때 조회 오류가 난다(§5). 판정 구간 밖 조회 오류의 처리 방식을 다음 세션 사전 등록에 넣는다.

## 9. 배운 점 (면접 답변용 한 줄)
