# TS-046 · 빈 공연 정리와 신규 진입이 겹치면 대기자가 있는 공연이 승격 대상에서 빠질 수 있었다

- 슬라이스: S03(대기열) — 외부 아키텍처 리뷰(2026-10-10)에서 지적, 코드로 확인
- 날짜: 2026-10-10
- 유형: 동시성 결함(확인 후 행동 사이 경합) — 코드 근거, 운영 재현은 하지 않음
- 관련: `QueueAdmissionService.tick`·`retireIfEmpty`, `QueueService.ISSUE_LUA`, [[TS-044]](같은 계열 — 확인 후 행동 경합)
- 상태: **해결** — 확인과 제거를 한 Lua로, 통합 테스트(CI)

## 1. 증상 (코드 근거)
승격 워커는 틱마다 활성 공연 목록(`queue:active-events`)을 돌며 회수·승격한 뒤, 대기 0·입장 카운터 0이면 그 공연을 목록에서 뺀다.
확인은 스냅숏 Lua(`SNAPSHOT_LUA`)로, 제거(`SREM`)는 별도 명령으로 했다. 신규 진입의 `ISSUE_LUA`(대기열 `ZADD` + `SADD active-events`)가
그 사이에 끼면 다음 순서가 가능했다.

1. 워커: 대기 0·입장 0 확인
2. 신규 진입: 대기열 등록 + `SADD`(이미 들어 있어 변화 없음)
3. 워커: 1의 결과로 `SREM` → **대기자가 있는데 공연이 목록에서 빠진다**

빠진 공연은 승격 워커가 돌지 않아, 그 공연에 다음 진입이 와서 `SADD`할 때까지 대기자가 승격되지 않는다(그 뒤 진입이 없으면 계속).
틈은 확인과 제거 사이(밀리초 단위)이고, 빈 공연에 첫 진입이 그 순간 들어와야 한다(추론 — 발생 빈도는 재지 않았다).

## 2. 해결
`RETIRE_IF_EMPTY_LUA`: `ZCARD wait == 0`이고 입장 카운터 ≤ 0일 때만 `SREM`한다 — 확인과 제거가 한 원자 단위다.
`ISSUE_LUA`·`TAKEOVER_LUA`(대기열에 넣는 유일한 두 경로 — 둘 다 같은 원자 단위에서 `SADD`)와 서로 원자라 진입은 확인 전(→ 대기 1이라 빼지 않음)이나 제거 후(→ `ISSUE_LUA`가 다시 `SADD`)에만 들어온다. 키는 모두 KEYS로 넘긴다.
틱의 스냅숏은 지표용으로 그대로 쓰고, 스냅숏이 비었을 때만 이 스크립트로 다시 확인해 뺀다.

## 3. 검증
- 통합 테스트(Testcontainers Redis, CI) `QueueActiveEventCleanupIntegrationTest` 3건: 빈 공연은 빠짐 / 비어 있음을 확인한 뒤 진입이 끼면 빼지 않고
  다음 틱에 승격됨(예전 순서를 결정적으로 재현) / 입장자가 남아 있으면 대기 0이어도 빼지 않음.
  테스트는 "제거할 때 다시 확인한다"를 본다. 확인과 제거의 원자성 자체는 Lua 구조(한 스크립트)로 보장되며 테스트로 따로 재지는 않았다.

## 4. 영향
- 빈 공연을 정리할 때만 Lua 1회가 더해진다(비어 있지 않은 공연은 예전과 같다). 부하 측정 경로(진입·상태 조회)는 바뀌지 않는다.
