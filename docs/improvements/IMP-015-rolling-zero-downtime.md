# IMP-015 · 롤링 배포 무중단 실측 — 3,600건 중 5xx 0건 (조건 한정)

- 슬라이스: S09(EKS 배포) — 인프라
- 날짜: 2026-08-08
- 유형: 정량(가용성 실측)
- 관련: [[ADR-012]](3AZ 인프라), `k8s/base/api-deployment.yaml`, [[TS-016]]·[[TS-017]](같은 배포에서 나온 결함)
- 상태: 부분 검증 — §5의 한 조건에서만 확인

## 1. 배경

매니페스트에 무중단을 위한 값들을 **짝으로** 맞춰 두었지만, 실제로 통하는지는 확인하지 않았다.
PR #179에 이렇게 적어 두었다.

> "5초가 그 창을 덮는다고 보장할 수는 없다 — 실제로 충분한지는 롤링 중 무중단 실측으로 확인해야 한다."

이 문서가 그 확인이다.

## 2. 검증 대상 — 짝을 맞춘 값들

| 설정 | 의도 |
|---|---|
| `maxUnavailable: 0` / `maxSurge: 1` | 새 Pod가 Ready된 **뒤에만** 옛 Pod를 뺀다 |
| `preStop: sleep 5` | SIGTERM 전에 멈춰 ALB 등록 해제가 **시작될** 시간을 번다 |
| `deregistration_delay = 10s` | 등록 해제 중 기존 연결을 드레이닝 |
| `terminationGracePeriodSeconds: 30`(web) | 위 둘보다 커야 SIGKILL이 앞지르지 않는다 |
| readiness `periodSeconds: 5`, `failureThreshold: 3` | 준비되지 않은 Pod로 트래픽이 가지 않게 |

## 3. 측정 방법

```
대상   https://flow-ticket.com/api/events/1678/seats   (좌석 100석 — DB를 실제로 타는 조회)
부하   병렬 6워커, 약 25 req/s
행위   부하 중 kubectl rollout restart deployment/flowticket-web
기록   요청별 (시각, 워커, HTTP 상태코드)
```

빈 목록 조회가 아니라 **좌석 조회**를 쓴 이유: DB를 거의 타지 않는 요청은 무중단의 증거로 약하다.

## 4. 결과

```
총 요청   3,600
200       3,600  (100%)
5xx           0
rollout   23:22:54 → 23:23:00  (web 파드 2개 교체, 새 ReplicaSet 확인)
```

**롤링이 실제로 일어났는지도 확인했다** — 새 ReplicaSet이 생기고 파드 2개가 교체됐다.
(첫 시도에서 `rollout status`가 6초 만에 끝나 의심스러워 ReplicaSet 이력으로 검증했다.)

## 5. ⚠️ 이 결과가 말하지 않는 것

**"무중단이 확인됐다"고 일반화할 수 없다.** 직전에 다른 조건에서 **502가 1건** 났다.

| | 502가 난 배포 | 이 측정 |
|---|---|---|
| 방식 | `kubectl apply` — **이미지 태그 변경** | `rollout restart` — 이미지 동일 |
| 범위 | **web + api 동시** | web 단독 |
| 부하 | 2.5 req/s (168건) | 25 req/s (3,600건) |
| 결과 | **502 × 1** | 0 |

이미지가 바뀌면 노드가 **이미지를 pull**하느라 Ready까지 더 걸리고, api까지 함께 롤링되면
web이 프록시하는 대상도 흔들린다. **그 조합에서만 나는 것일 수 있다.**

정확히 말할 수 있는 것은 두 가지다.
- **이미지 동일 + web 단독 롤링**: 25 req/s에서 3,600건 무중단
- **이미지 변경 + web·api 동시 롤링**: 168건 중 1건 502

**후자는 원인을 규명하지 않았다.** 재현 조건을 좁히려면 이미지를 다시 바꿔 롤링해야 한다.

## 6. 한계

- **측정 지점이 인터넷 밖**이다(내 PC → ALB). 네트워크 요인을 배제하지 못한다.
- **부하가 낮다.** 25 req/s는 선착순 트래픽과 거리가 멀다 — S10 부하테스트에서 다시 봐야 한다.
- **web만 롤링했다.** api 롤링 중 무중단은 별도로 확인해야 한다.
- **단발 측정**이다. 502는 168건에 1번 났다 — 3,600건 0건이 "0%"를 뜻하지 않는다.
