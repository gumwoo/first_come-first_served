# TS-048 · 연속 머지에서 앞 머지의 앱 변경이 이미지로 나가지 않았다 — 변경 판별이 직전 커밋만 봤다

- 슬라이스: 배포 파이프라인(ADR-009) · 관련: [[TS-029]](CI 동시성·stale 배포)
- 날짜: 2026-10-10
- 유형: CI/CD 결함(배포 누락) — 측정 세션 시작 전 ECR 태그 대조에서 발견
- 상태: **해결** — 판별 기준을 배포된 태그로

## 1. 증상 (실행 기록 근거)
#386(대기열 상태 판정, `apps/api` 변경)과 #387(알림 테스트, harness·docs만)을 연달아 머지했다.
ECR의 최신 api 이미지는 그 전 머지(8379ab4)였고, 오버레이 `newTag`도 8379ab4였다 — #386 코드가 배포 대상에 없었다.
- 361898f(#386 머지)의 CI: `cancelled` — 바로 뒤 push에 밀려 취소(`ci.yml`의 `cancel-in-progress: true`). Image는 CI `success`에서만 돌므로 실행 자체가 없었다.
- 37adccd(#387 머지)의 Image: `guard`가 `git diff HEAD^ HEAD`를 보고 harness·docs뿐이라 "영향 없음"으로 건너뜀.
같은 일이 #379(8551c21, CI `cancelled`)에서도 있었다. 이때는 #385가 다시 `apps/api`를 건드려 8379ab4 이미지에 함께 실렸다(우연).
두 경우 모두 2026-10-08 클러스터 철거 뒤라 측정에 쓰인 이미지는 없다.

## 2. 원인
CI 취소는 의도된 동작(같은 브랜치의 오래된 실행은 버린다)이고, 그 커밋의 변경은 다음 커밋의 CI가 함께 검증한다.
그런데 Image의 변경 판별은 "직전 커밋 대비"라, 취소된 커밋의 변경이 다음 커밋의 판별 범위에서 빠졌다.
판별이 물어야 할 것은 "이 커밋이 직전 커밋과 다른가"가 아니라 "**지금 배포된 것**과 다른가"다.

## 3. 해결
`image.yml` `guard`: 비교 기준을 오버레이의 현재 `newTag`(배포된 SHA)로 바꿨다(`fetch-depth: 0`).
태그를 못 읽거나 조상이 아니면 판별 근거가 없으므로 빌드한다 — 실제로 태그를 덮을지는 bump-tag의 조상 검사가 다시 판정한다(TS-029).

## 4. 검증
- 최근 main first-parent 12개 커밋에 옛/새 판별을 그대로 재현(로컬 git): 37adccd 옛=skip → 새=build, 361898f·8379ab4 등 앱 변경 머지는 둘 다 build,
  배포 태그 커밋(`chore(deploy)`)·태그 이후 문서만 바뀐 머지(bca9ac4)는 둘 다 skip. #379 이후 문서 머지 4건(a46bb03~622fd9a)은 새 판별이 build —
  그 시점 배포 태그(d6c229c)에 #379가 없었으므로 빌드가 맞다.
- 워크플로 실제 실행은 머지 후 다음 앱 변경 머지에서 확인(이 PR 자체는 `image.yml` 변경이라 build로 판정된다).
