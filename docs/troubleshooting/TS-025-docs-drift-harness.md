# TS-025 · 하네스가 코드↔계약은 잡는데 문서↔현재 상태는 못 잡았다

- 슬라이스: 전반(문서 규율) — 발견은 2026-08-12 리뷰
- 날짜: 2026-08-12
- 유형: 프로세스 결함 — **규칙의 사각지대**
- 관련: [[TS-022]](사건 → 하네스 규칙 ⑧을 만든 선례), [[TS-024]](이번 드리프트의 원인 중 하나),
  [`harness/docs/check.mjs`](../../harness/docs/check.mjs)
- 상태: **해결** — 드리프트 4건을 고치고 하네스 규칙 ⑯·⑰을 추가했다

## 0. 무엇이 드러났나

리뷰어의 지적은 이랬다.

> 코드↔계약 drift는 잘 잡는데 **문서↔현재 구현 상태 drift는 아직 완전히 못 잡고 있다.**

확인해보니 지적이 전부 맞았고, 세어보니 **하나 더 있었다.**

| # | 위치 | 문서의 주장 | 실제 |
|---|---|---|---|
| 1 | `k8s/README.md` §아직 없는 것 | Kafka CR·ArgoCD Application·kube-prometheus-stack·ExternalSecret **네 개 다 없다** | **네 개 다 실존** |
| 2 | `k8s/README.md` §시크릿 | "ESO가 동기화한다(08-11~)" **와** "ESO 연결은 목표이고 아직 하지 않았다"가 **같은 절에 공존** | ESO는 이미 동작 중 |
| 3 | `k8s/README.md` §REPLACE_* | `REPLACE_ECR_REGISTRY`가 남아 있고 "공개 저장소라 placeholder로 둔다" | 그 placeholder는 **없다.** 레지스트리는 오버레이에 실제 값(계정 ID 포함)으로 커밋돼 있다 |
| 4 | `IMP-004` §8-1 | `TS-024 (미수정)` | TS-024는 `상태: 해결` |

**4번은 내가 만들었다.** 같은 날 오전에 `(미수정)`이라고 쓰고 오후에 TS-024를 고치면서
IMP-004를 따라 고치지 않았다. 드리프트는 몇 년에 걸쳐 쌓이는 게 아니라 **몇 시간 만에** 생긴다.

3번은 성격이 조금 다르다. 계정 ID는 자격증명이 아니라 식별자라 비밀 규칙(ADR-013) 위반은
아니다. 그러나 **문서가 "숨겼다"고 말하는데 실제로는 커밋돼 있는 상태**는 읽는 사람이 저장소의
노출 범위를 잘못 알게 만든다.

## 1. 왜 하네스가 못 잡았나 — 방향이 한쪽뿐이었다

문서를 안 본 게 아니다. 이미 두 규칙이 있었다.

| 규칙 | 검사 | 방향 |
|---|---|---|
| ⑨ | `CREATE TABLE x` → `docs/db/x.md` 존재 | 코드 → 문서 |
| ⑮ | 코드·마이그레이션의 `TS-014` 참조 → 그 문서 실존 | 코드 → 문서 |

**둘 다 "코드가 가리키는 문서가 있느냐"만 본다.** 규칙 ⑮의 주석은 이렇게 적혀 있다.

> 근거를 가리키는 척하는 주석은 근거가 없는 것보다 나쁘다(찾는 시간까지 쓰게 만든다).

맞는 말이고, **반대 방향에도 똑같이 맞는 말이었다.** 문서가 코드의 상태를 단언하는 경우는
아무도 보지 않았다. 그래서 위 네 건이 CI를 통과해 머지됐다.

정리하면 원인은 **문서의 양**이 아니라 **검사의 방향**이다. 양이 많아 놓친 게 아니라,
그 방향은 애초에 검사 대상이 아니었다.

## 2. 조치 — 규칙 ⑯·⑰ (`harness/docs/check.mjs`)

### ⑯ "아직 없다"고 단언한 경로가 실존하면 실패

자연어로 "없다"고 쓰면 기계가 못 읽는다. 그래서 **경로를 백틱으로 적는 것**을 규약으로 삼고,
`## 아직 없는 것` 류 절 안의 백틱 경로만 검사한다.

```
없다고 단언한 대상이 실존한다: k8s/README.md — "kafka/kafka.yaml"
  (실제: k8s/kafka/kafka.yaml). 문서를 현재 상태로 고칠 것
```

규약을 안 지킨 문서는 보호받지 못한다. 대신 지킨 문서는 **파일이 생기는 순간** CI가 알려 준다.

### ⑰ 참조에 붙인 상태 표기 ↔ 대상 문서의 상태 줄

`IMP-004`가 `TS-024`를 `(미수정)`으로 가리키는데 TS-024 머리말이 `상태: 해결`이면 둘 중 하나가
거짓이다. 양쪽 다 정형 필드라 대조할 수 있다.

## 3. 규칙을 두 번 고쳐야 했다 — 초안은 오탐을 냈다

**첫 버전은 실제 저장소에서 4건을 잡았고 넷 다 오탐이었다.**

```
TS-018  상태: 원인 규명 완료 — **수정은 하지 않음**(§6)     ← _index.md는 "(보류)"
ADR-011 상태: 구현 완료 · 통합테스트 통과 / 실 PG 실증은 미실시  ← _index.md는 "(미실시)"
```

상태 줄은 **끝난 것과 안 끝난 것을 한 문장에 담는 경우가 많다.** 초안은 '완료'만 보고
"참조는 미해결이라는데 대상은 완료"라고 판정했는데, 실제로는 **서로 맞는 말**이었다.

→ 상태 줄에 미해결 표현이 하나라도 있으면 **양립으로 보고 넘어간다.** 놓치는 경우는 생기지만,
노리는 것은 "대상은 완전히 끝났는데 참조는 아직이라고 말하는" 명백한 모순이다.

**두 번째 오탐은 fixture가 잡았다.**

```
TS-902는 이미 해결됐으므로 위 "(미수정)"은 거짓이다.   ← 이 설명 문장이 걸렸다
```

같은 줄에 참조와 표기가 있기만 하면 걸리는 구조였다. → **인접성을 요구**하도록 바꿨다
(참조 바로 뒤, 마크다운 링크 `](경로)`만 사이에 허용). 드리프트는 **참조 옆에 붙인 딱지**에서
생기지 본문 설명에서 생기지 않는다.

**세 번째 오탐은 이 문서가 냈다.** 위 §0의 표에서 드리프트를 **증거로 인용**했는데
(`| 4 | IMP-004 §8-1 | TS-024 (미수정) | ... |`), 규칙이 그 인용을 현재 상태에 대한 단언으로
읽고 잡았다. → **코드블록과 인라인 코드는 검사에서 제외**하도록 고쳤다. 과거 상태를 옮겨 적는
자리는 문법적으로 인용이고, 인용까지 단언으로 보면 **사건을 기록하는 문서를 쓸 수 없게 된다.**

> **오탐을 내는 규칙은 곧 꺼진다.** 꺼진 규칙은 없는 규칙보다 나쁘다 — 있다고 믿게 만들기
> 때문이다. 그래서 두 번 다 "덜 잡더라도 틀리게 잡지 않는" 쪽으로 좁혔다.

## 4. 다루지 않은 것

- **자연어 자기모순**(위 표 2번: "했다" vs "아직 안 했다")은 **정적 규칙으로 판정할 수 없다.**
  이건 규칙이 아니라 리뷰의 몫이다. 문서 2번은 손으로 고쳤고 규칙으로는 못 막는다.
- ⑯은 **경로를 백틱으로 적은 경우만** 본다. 자연어로만 "아직 없다"고 쓰면 여전히 못 잡는다.
- ⑰은 **부분 완료 상태를 일부러 놓친다**(§3). 정확도를 위해 재현율을 포기했다.

## 5. CI 배치 — 하마터면 무용지물이 될 뻔했다

이 검사를 `backend` 잡에 두려다 멈췄다. **이 규칙이 필요한 순간이 바로 "문서만 고친 PR"인데,
그런 PR은 변경 영역 필터에 걸려 `backend`·`frontend`가 전부 skip된다.** 거기 뒀으면 정작
필요할 때 돌지 않았을 것이다.

`harness-meta` 잡은 `needs`·`if` 없이 **항상 실행**되고 이 검사는 1초 미만이라, 그쪽에 뒀다.

## 6. 배운 점

**규칙이 있다는 것과 그 규칙이 옳은 방향을 본다는 것은 다르다.** 이 저장소는 하네스를 자랑거리로
삼아 왔는데, 정작 문서 드리프트는 하네스가 있다는 사실 때문에 **더 늦게 발견됐다** — "검사가
있으니 괜찮겠지"가 사각지대를 가렸다.

그리고 검사 도구를 만들 때는 **자기 저장소에 먼저 돌려봐야 한다.** 초안을 실제 docs/에 돌리지
않고 fixture만으로 확인했다면 오탐 4건을 모르는 채 머지했을 것이고, 그 규칙은 첫 실패에서
꺼졌을 것이다.
