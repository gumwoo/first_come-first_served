## 1. 상황 (Context)
1차 평가([[IMP-044]])에서 AI는 CPU 장애 6회를 모두 다른 원인으로 판정했고, 정상 run 3회를 판단 불가로 냈다. 다음 세 가지를 바꾸고 새 run으로 다시 평가했다.
- 요약에 api 컨테이너가 CPU 할당량에 막힌 주기 비율을 넣었다. cgroup `cpu.stat`(`nr_periods`·`nr_throttled`)을 호스트 cgroup 이름공간의 별도 컨테이너에서 1초마다 읽는다(`api.cgroup.throttled_period_ratio`, 초 단위 최댓값 `throttled_period_ratio_max`).
- 규칙 분류기는 이 비율이 0.2를 넘으면 Redis·DB 갈래보다 먼저 app_cpu로 판정한다. 0.2는 개발용 run(정상 0~0.1, CPU 장애 0.75·1.0)으로 정했다.
- 대조기는 참·거짓 근거를 1·0으로 대조한다. 프롬프트 v4는 새 필드의 뜻과 "근거는 숫자 필드만"을 적고, 정상 기준을 정상 run 9회(cgroup 항목은 6회)의 범위로 넓혔다.
  새 필드 설명에는 할당량에 막힌 컨테이너는 CPU 사용량이 낮게 보이고, CPU 부족은 사용량보다 이 비율로 판단하며, 앱이 CPU를 못 받으면 Redis·DB 지표가 같이 오를 수 있다는 해석(요지)을 함께 넣었다. 4.1의 AI 결과는 이 설명을 받은 상태의 결과다.

## 2. 문제 정의 + 분류
- 계층: 운영 도구(분석). 서비스 코드와 무관하다.
- 질문: 바꾼 뒤 같은 요약에서 AI와 규칙 분류기가 각각 원인을 얼마나 맞히는가. 정상 run을 원인으로 잘못 판정하지 않는가.

### 4.1 CPU 장애
- CPU 장애 6회의 할당량에 막힌 주기 비율은 0.23~0.69, 초 단위 최댓값은 6회 모두 1이었다. 정상 run 6회는 비율 0~0.05였다.

- 규칙은 6회 중 5회를 맞혔다. 이 중 2회(2c3f772c, 4fbff263)는 할당량 갈래가 없으면 각각 redis(Redis 명령 완료 평균 5.39ms)·db(PostgreSQL 활성 평균 0.64)로 판정된다(같은 요약에서 cgroup 항목을 빼고 규칙을 다시 돌려 확인).

## 5. 조치
- 원인 판정은 규칙 분류기를 기준으로 두고, AI는 판정과 함께 근거·반대 지표·확인 항목을 정리하는 데 쓰는 경계([[ADR-029]])를 유지한다. 파이프라인(규칙 → AI)의 결과는 장애 15/16, 정상 오탐 0이다.
- 요약에 할당량에 막힌 주기 비율을 넣고, 규칙에 할당량 갈래를 먼저 두는 변경을 채택한다(4.1).
- 기본 모델은 Haiku 5.5로 둔다. Sonnet 5.5 참고 채점은 장애 정답이 같고 비용이 약 12배였다(4.4).
- `eval.mjs`의 공개 단가 표에 Sonnet 5.5를 더해, 모델을 바꿔 채점해도 비용이 계산되게 했다.

- 장애 정답 규칙 8/9, AI 9/9, 파이프라인 8/9. 정상 오탐은 모두 0/3이고, AI 근거 수치 대조 실패는 0이다.
- 규칙이 놓친 1건(91981ef0, cpu 강도 1)은 할당량에 막힌 주기 비율이 0.21로 기준(0.2)을 넘었지만, 예매 p95 중앙값 999ms가 이상 판단 기준(1,500ms) 이하라 정상으로 끝났다. f7c9a769(비율 0.23, p95 중앙값 1,408ms)와 같은 모양이다.
- 평균 토큰은 입력 4,246·출력 2,997, 비용은 합계 $0.0231이다(공개 단가로 계산).

### 8.5 도구 처리 시간
- AI 결과 파일이 순차 호출로 하나씩 쓰인 시각의 간격으로 run당 처리 시간을 쟀다. 요약 계산·AI 호출·대조를 포함하고, 파일 수정 시각으로 잰 근삿값이다.
- 8.3 채점: 23간격 7.9~18.2초(중앙값 14.3초). 8.4 run: 11간격 7.9~18.8초(중앙값 13.4초).

### 8.6 조사 시간 측정(사전 등록 B)은 하지 않는다
- B는 같은 run을 그래프만 볼 때와 그래프 + 도구 결과를 볼 때, 사람이 원인과 근거를 적기까지 걸리는 시간을 비교하는 측정이었다. 과제 12개 중 1개를 기록한 뒤 진행하지 않기로 했고, 기록된 1건은 결과로 쓰지 않는다.
- 판단하는 사람이 도구를 만든 본인 한 명이고 장애 범주와 지표 패턴을 이미 알고 있어(사전 등록에 적은 한계), 조건별 6회로는 시간 차이를 도구 효과로 읽기 어렵다고 판단했다.
- 평가는 규칙 분류기와 AI의 판정 정확도(8.3·8.4)와 도구 처리 시간(8.5)으로 둔다. 사람의 조사 시간이 줄었는지는 재지 않았다.
