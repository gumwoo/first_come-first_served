# TS-043 · 입장 토큰 하나로 여러 계정이 좌석을 잡을 수 있었다 — 좌석 게이트와 이탈이 토큰 주인을 확인하지 않았다

- 슬라이스: S03(대기열)·S04(좌석) — 플랫폼 검증 뒤 코드 리뷰에서 발견
- 날짜: 2026-10-09
- 유형: 인가 결함(소유권 미확인) — 코드 근거로 확인, 운영 재현은 하지 않음
- 관련: `QueueService.isAdmitted`·`leave`, `QueueAdmissionService.admit`, `SeatService.hold`, `QueueController`, [[ADR-002]]
- 상태: **해결** — 좌석 게이트·이탈에 주인 확인, 승격 때 메타 수명 연장, 통합 테스트로 확인

## 1. 증상 (코드 근거)
- 좌석 선점 `SeatService.hold(userId, eventId, seatIds, queueToken)`은 로그인한 `userId`를 받으면서도 게이트에는
  `queueService.isAdmitted(queueToken, eventId)`만 넘겼다. 게이트는 토큰이 그 공연에 입장했는지만 보고 **누구의 토큰인지는 보지 않았다**.
- 이탈 `DELETE /queue/token?token=`은 로그인만 요구하고 `leave(token)`은 토큰 메타의 주인을 요청자와 맞추지 않았다.

## 2. 왜 문제인가
- **대기열 우회**: 한 회원이 대기열을 통과해 받은 입장 토큰을 다른 계정들이 같이 쓰면, 그 계정들은 줄을 서지 않고 좌석을 잡는다.
  1인 구매 한도는 계정 단위라 이 경로를 막지 못한다. 대기열이 지키려는 "정원만큼만 downstream으로"가 계정 수만큼 늘어난다(추론).
- **남의 대기·입장 지우기**: 토큰을 알게 된 다른 회원이 이탈 API로 그 사람의 대기 순번이나 입장 슬롯을 없앨 수 있다.
- 토큰은 추측하기 어려운 UUID지만, 공유·유출을 막는 것은 토큰 비밀성 하나뿐이었다. 상태 조회(`GET /queue/status`)가 토큰만으로
  열려 있는 것은 폴링 비용 때문의 의도된 결정(ADR-002)이지만, 좌석·이탈처럼 **상태를 바꾸는 경로**는 로그인 회원이 있으니 주인을 맞출 수 있다.

## 3. 해결
- `isAdmitted(token, eventId, requesterId)`: 토큰 메타의 `userId`가 요청 회원과 같을 때만 기존 입장 판정을 한다. 다르거나 메타가 없으면 거부
  (`QUEUE_NOT_ADMITTED` — 토큰이 유효한지 드러내지 않는다). 메타 조회는 `HMGET userId eventId` 한 번으로, 폴백의 소속 이벤트 확인에도 쓴다.
- `leave(token, requesterId)`: 주인이 아니면 `FORBIDDEN`, 대기·입장 상태는 건드리지 않는다.
- **메타 수명**: 메타 TTL(`queue.token-ttl`, 1,800초)은 발급 시각부터 센다. 오래 기다린 뒤 승격되면 입장창(300초) 도중에 메타가 사라져
  정상 회원의 선점이 거부될 수 있다. 그래서 승격 때 `EXPIRE <meta> (admitTtl + 60) GT`로 메타가 입장창보다 오래 살게 한다
  (이미 더 길면 그대로, 메타가 없으면 아무것도 하지 않는다 — Redis 7.0+, 로컬·CI 7.4 / ElastiCache 7.1).
  메타가 이미 없는 토큰이 승격되는 경우(수명이 다한 토큰 — 대기 토큰 수명주기 문제, 별도 수정)는 주인을 확인할 수 없으므로 거부된다.

## 4. 검증
- 통합 테스트(Testcontainers Redis) `QueueTokenOwnershipIntegrationTest`: 주인만 게이트 통과, 메타 없는 토큰 거부, 승격 때 메타 수명 연장
  (5초 → 입장창 이상), 더 긴 수명은 줄이지 않음, 남의 토큰 이탈은 `FORBIDDEN`이고 대기·입장 상태 유지.
- `SeatInventoryIntegrationTest`: 다른 회원의 입장 토큰으로 선점 → `QUEUE_NOT_ADMITTED`, 주인은 그대로 선점 성공.
- 기존 대기열·좌석·주문 테스트는 모두 같은 회원이 발급·선점하므로 시그니처만 바뀌었다.

## 5. 영향·한계
- Redis 비용: 승격 1건당 명령이 하나 늘고(`EXPIRE GT`, 틱당 최대 정원 수), 좌석 게이트 정상 경로는 `HMGET` 1회가 더해져 1 → 2왕복이다
  (폴백 경로는 `ZSCORE·EXISTS·HGET` → `HMGET·ZSCORE·EXISTS`로 3왕복 그대로). 부하 시험은 이 변경 **전** 이미지로 잰 결과이며
  ([[IMP-029]] `874a980`, [[IMP-031]] `419c96b` — 둘 사이 api 코드 변경 없음), 바뀐 비용은 재측정하지 않았다
  (선점·승격은 정원 단위라 작다고 본다 — 추론).
- 승격 Lua와 메타 연장 사이에 파드가 죽으면 연장이 빠진다 — 오래 기다린 토큰만 영향(추론).
- 롤링 배포 중 구버전 파드가 승격한 토큰은 메타 수명 연장이 없다. 입장창 동안 메타가 남아 있으면 영향이 없고, 발급 뒤 25~30분에 승격된 토큰만
  선점이 거부될 수 있다(추론, 배포 순간에 한정).

## 6. 재발 방지
- 상태를 바꾸는 대기열·좌석 경로는 로그인 회원과 토큰 주인을 맞춘다(도메인 규칙 S03에 추가). 소유권 테스트를 회귀로 남긴다.
