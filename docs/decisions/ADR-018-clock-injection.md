# ADR-018 · 시간의 출처를 주입한다 — 판정 기준을 테스트에서 고정하기 위해

- 상태: **Accepted** (서비스 계층 적용 완료 / 엔티티 타임스탬프는 범위 밖 — 아래 §한계)
- 날짜: 2026-09-21
- 슬라이스: 횡단(S04·S05·S06·S08)
- 관련: [[TS-039]](시스템 존 직렬화), [[ADR-011]](정산 유예·소급 한계), [[ADR-006]](상태 전이)

## 맥락

이 도메인에서 시간은 부수적인 값이 아니라 **판정 기준**이다.

| 판정 | 기준 |
|---|---|
| 좌석 선점 만료 | `expiresAt < now` |
| 주문 결제 제한시각 | `expiresAt < now` |
| 환불 가능 여부 | 공연일 − `now` |
| 대기열 입장 TTL | `admitExp > now` |
| 정산 유예·소급 한계 | `createdAt`이 창 안인가 |

코드가 `LocalDateTime.now()`를 직접 부르면 이 판정을 테스트에서 고정할 수 없다. 경계를 확인하려면
`sleep`을 넣거나 DB의 시각 컬럼을 손으로 과거로 밀어야 하는데, 후자는 **"만료로 판정하는가"가 아니라
"이미 만료된 행을 쓸어담는가"**만 확인한다. 판정 자체는 검증되지 않은 채 남는다.

## 결정

1. **`Clock` 빈 하나를 두고 시간에 의존하는 서비스에 주입한다.** `LocalDateTime.now()` →
   `LocalDateTime.now(clock)`, `Instant.now()` → `Instant.now(clock)`.
2. **`Clock.systemDefaultZone()`이다. `systemUTC()`가 아니다.** 이 애플리케이션은 시각을 시스템 존
   기준으로 저장·직렬화한다([[TS-039]]). UTC 시계를 주입하면 `LocalDateTime.now(clock)`이 KST 환경에서
   9시간 과거가 돼 **방금 만든 홀드가 만료로 판정된다.** 컴파일로는 드러나지 않고 배포에서만 깨지므로
   단위 테스트로 못박았다(`ClockConfigTest`). 컨테이너 TZ는 k8s에서 고정한다(하네스 k8s 규칙 7).
3. **기록과 판정 기준을 가른다.** 엔티티 생성자의 `createdAt`·`updatedAt`은 그대로 둔다. 여기에 시계를
   넣으려면 엔티티가 스프링 빈을 알아야 하는데, 이 값들은 **기록**이라 얻는 것이 비용에 못 미친다.
   반대로 **판정 기준이 되는 시각은 호출자가 넣는다.**
   - `expiresAt`·`paidAt` — 서비스가 계산해 넣는다(원래 그랬다).
   - `Event.detailSyncedAt` — "다시 수집할 때가 됐는가"의 기준이다. `KopisDetailSyncer`가 시계로
     stale 경계를 계산하므로, 엔티티가 `now()`를 직접 부르면 같은 판정을 두 시계가 나눠 갖는다.
     `updateDetail(..., syncedAt)`으로 바꿨다.
   - `refund_attempts.created_at` — 정산 후보의 창을 가른다([[ADR-011]]). INSERT가 DB의 `now()`를
     쓰고 있어 같은 문제가 있었다. 앱 시계 값을 넘긴다.

   판단 기준은 "그 값을 누가 읽고 무엇을 결정하는가"다. 아무도 비교하지 않는 값은 기록이다.

## 고려한 대안

- **`@MockBean Clock`으로 테스트마다 스텁한다.** 빈을 바꾸지 않아도 된다. 채택하지 않았다.
  `instant()`·`getZone()`을 매번 스텁해야 하고, 스텁을 빠뜨리면 `null`이 흘러 엉뚱한 곳에서 터진다.
  테스트에서는 앞으로 돌릴 수 있는 작은 `Clock` 구현을 `@Primary`로 얹는 편이 읽기 쉽다.
- **시간을 파라미터로 넘긴다**(`RefundPolicy.quote(..., now)`가 이미 이 방식이다). 순수 함수에는 좋지만
  호출 경로가 긴 서비스까지 모두 파라미터를 뚫으면 시그니처가 오염된다. 경계(정책·계산)는 파라미터,
  진입점(서비스)은 주입으로 나눴다.

## 결과 / 한계 (정직)

- **동작은 바뀌지 않는다.** 기본 빈이 `systemDefaultZone()`이라 주입 전과 같은 시각을 돌려준다.
  이 변경의 값은 전부 **테스트 가능성**이다.
- **기존 테스트가 이 방식으로 다시 쓰이지는 않았다.** 시각을 DB에서 밀던 테스트들은 그대로 둔다.
  새로 쓰는 시간 경계 테스트부터 시계를 옮기는 방식을 쓴다(`SeatHoldExpiryClockIntegrationTest`).
- **순수한 기록용 타임스탬프는 여전히 고정할 수 없다.** 위 3번의 선택이다. 기록이던 값을 나중에
  판정에 쓰기 시작하면 그때 경계를 옮겨야 하는데, **그 전환은 조용히 일어난다** — `refund_attempts`가
  실제로 그랬다. 새 컬럼을 비교에 쓰기 시작할 때 이 ADR을 다시 볼 것.
- **Redis TTL·DB `now()`는 이 시계를 따르지 않는다.** 대기열 키의 `EXPIRE`, 마이그레이션의 `now()`는
  각각 Redis·Postgres의 시계다. 시계를 옮긴 테스트에서 그 둘은 실제 시간으로 흐른다.
