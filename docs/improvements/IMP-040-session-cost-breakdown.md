# IMP-040 · 측정 세션 1회 비용 분해: 노드보다 발생기·Redis·세션 길이가 크다

- 슬라이스: `S10`(부하·확장)
- 날짜: 2026-10-20
- 유형: 정량(계산). 리소스 목록(Terraform·매니페스트·철거 로그)에 AWS 공개 가격표 단가를 곱했다. 모든 금액은 계산값이다.
- 관련: [[IMP-032]](노드-시간), [[IMP-039]](평시 노드 절감 보류), [ADR-012](../decisions/ADR-012-3az-eks-infra-cost-control.md)(3 AZ·NAT·휘발 플랫폼), [TS-049](../troubleshooting/TS-049-redis-cpu-credit-exhaustion-in-loadtest.md)(Redis m7g.large), `infra/terraform/platform/environments/demo/loadtest.tfvars`
- 단가 출처: AWS Price List 공개 파일(로그인 불필요, `pricing.us-east-1.amazonaws.com/offers/v1.0/aws/<서비스>/current/ap-northeast-2/index.csv`, 발행 2026-09-28), 서울 온디맨드.
  EC2·RDS 파일은 스트리밍으로 필요한 행만 걸렀다. 이전 문서의 기록값(m6i.large $0.118, IMP-032 / cache.m7g.large $0.192, TS-049)과 일치한다.
- 벤치 파일: 레포 밖 `artifacts/loadtest/_inventory/prices-20261020/`. 서비스별 가격표 CSV(EKS·VPC·ELB·ElastiCache·Secrets Manager), EC2·RDS에서 거른 행(`ec2-picked.txt`·`rds-picked.txt`), 거르는 스크립트 `pick.js`

## 1. 상황 (Context)
ADR-012에 따라 플랫폼(VPC·EKS·RDS·ElastiCache·ALB)은 측정 세션마다 만들고 지운다. 그래서 실제로 돈이 나가는 단위는 "측정 세션 1회"다.
지금까지의 비용 최적화([[IMP-037]]~[[IMP-039]])는 평시 노드 수를 줄이는 쪽이었다.
이 문서는 노드의 몫을 포함해 세션 시간당 비용을 항목별로 나눠, 어디를 줄여야 효과가 있는지 정한다.

## 2. 문제 정의 + 분류
- 계층: 인프라 비용(시간당 고정 + 사용량).
- 질문: 측정 프로파일로 올린 세션에서 시간당 얼마가 어디로 나가는가. 줄일 수 있는 항목과 줄이면 안 되는 항목(설계 결정에 묶인 항목)은 무엇인가.

## 3. 계산 방법
- 리소스 목록: `apply -var-file=loadtest.tfvars`가 만드는 84개 리소스(2026-10-17 철거 로그 `84 destroyed`)와 세션 중 Terraform 밖에서 생기는 것(ALB, Prometheus PVC)을 셌다.
  크기는 철거 로그의 상태값으로 확인했다.
- 시간당 고정비 = 수량 × 시간 단가. 월 단가(GB-월, 비밀 1개-월)는 730시간으로 나눴다.
- 사용량 과금(NAT·엔드포인트 처리 GB, AZ 간 전송, ALB LCU, CloudWatch 로그 수집)은 금액에 넣지 않고 단가만 적는다.

### 실제 세션 길이에 대입(계산, 구성 가정: 세션 내내 평시 5대 + 발생기 3대, Redis는 세션 당시 사양)
- Redis 사양: 측정 프로파일의 cache.m7g.large 전환(`7468c1a`, 2026-10-13, TS-049) 전 세션은 cache.t4g.micro × 2($0.024/h, 2노드 $0.048/h)였다. 그 세션은 시간당 $1.725로 계산한다.
- 길이 출처: 각 세션 `session.log`의 apply 시작 ~ 철거 완료.
  - 20261017-b100k: 2시간 11분 → 약 $4.5.
  - 20261010-1440(Redis t4g.micro): 3시간 37분 → 약 $6.2.
  - 20261014-ab: 8시간 5분 → 약 $16.6.
  - 20261015-nok: 11시간 53분 → 약 $24.5.
- 20261005-1440 ~ 20261007-platform(약 59시간, 같은 클러스터, Redis t4g.micro)은 발생기가 1~3대로 바뀌어 위 가정이 맞지 않는다. 발생기 1대로 잡으면 약 $78, 3대면 약 $102다(범위만).
- 실제 부하를 거는 시간은 run당 수 분이다. 나머지는 준비·분석·문서 작업 동안 켜 둔 시간이다(세션 기록 기준).

## 5. 줄일 수 있는 것 / 줄이면 안 되는 것
- **발생기는 부하를 걸 때만 켠다**: 효과가 가장 크다.
  - 발생기 3대는 세션 내내 $0.587/h다. run 묶음 사이에 인스턴스를 중지하면 그 시간만큼 줄어든다(`scripts/loadtest/loadgen.sh stop` / `start`).
  - 개수를 0으로 내리는 방식(Terraform `loadgen_instance_count=0`)은 결과 버킷까지 지우므로 쓰지 않는다. 중지 중에는 루트 EBS(gp3 30GiB, 3대 약 $0.011/h)만 과금된다.
  - 예: 4시간 세션에서 부하 시간이 1시간이면 약 $1.8 절감(계산).
  - 다시 켤 때는 인스턴스 기동과 SSM 재연결을 기다린다(`start`가 SSM Online까지 기다린다). checkout한 저장소와 k6는 루트 볼륨에 남는다.
- **Redis 엔진을 Valkey로 바꾸면 같은 사양이 20% 싸다**: 호환성 검증이 필요하다.
  - 같은 cache.m7g.large가 Redis는 $0.192/h, Valkey는 $0.1536/h다(같은 가격표). 2노드 기준 $0.384 → $0.307/h, 약 −$0.077/h(세션의 약 4%).
  - 이 프로젝트의 Lua 스크립트(입장 제어·발급)와 Lettuce 클라이언트의 Valkey 동작은 클라우드에서 검증한다.
- **세션 길이**: 세션 비용은 시간에 정비례한다. 같은 구성에서 11시간 53분 세션은 2시간 11분 세션의 약 5.4배다(계산).
  - 철거는 사용자 지시로만 한다(운영 규칙). 그래서 할 수 있는 일은 측정이 끝나면 결과 보고와 철거 판단 요청을 바로 올리는 것이다.
  - 분석·문서 작업은 철거 뒤로 미룬다(원자료는 철거 전에 내려받는다).
- **줄이지 않는 것(설계 결정에 묶임)**:
  - NAT 3 → 1: −$0.128/h(NAT 2개와 EIP 2개, 약 6%). 그러나 ADR-012 결정 2가 AZ별 NAT로 정했다(원문: "AZ 개수와 NAT 개수를 일치시켜야". 단일 NAT면 한 AZ 장애가 다른 AZ까지 막는다).
  - RDS·Redis Multi-AZ: 페일오버 실증(ADR-012)의 전제다.
- **판단 보류**:
  - ECR Interface 엔드포인트 6개(ecr.api·ecr.dkr × 3 AZ, $0.078/h)를 빼면 NAT로 넘어가는 것은 ECR API·매니페스트 트래픽뿐이다. 이미지 레이어는 S3 경로라 무료인 S3 Gateway 엔드포인트가 계속 받는다(`modules/endpoints/main.tf` 주석).
  - 그래서 비교할 양은 ecr.api·ecr.dkr 트래픽이다. 그 트래픽이 시간당 약 1.6GB(0.078 ÷ (0.059 − 0.01), 계산)를 넘어야 엔드포인트가 이득이다.
  - 매니페스트·API 호출은 레이어보다 훨씬 작으므로 엔드포인트를 빼는 쪽이 쌀 가능성이 크다(추론). 엔드포인트를 둔 이유에는 비용 외의 개선 목적도 있어(ADR-012 "개선") 판단은 보류한다.
- **조사 필요**: 컨트롤 플레인 로그 5종의 CloudWatch 수집량. 측정 프로파일에서 audit을 끄는 것은 증거(감사 로그) 손실과 맞바꾼다.
- **세션 사이 영속 리소스**(Route53 Zone, ECR 저장, S3 tfstate·ALB 로그 약 5GB, DynamoDB 잠금): 금액에 넣지 않았다. 월 단위 소액으로 본다(추정).

## 6. 조치
- 설정 변경은 없다. 다음 측정 세션의 운영 절차 후보로 둔다.
  1. 발생기는 run 묶음 때만 켠다. `scripts/loadtest/loadgen.sh stop`·`start`를 추가했다.
  2. 측정이 끝나면 결과 보고와 함께 철거 판단을 바로 요청하고, 문서 작업은 철거 뒤에 한다.
- Valkey 전환과 컨트롤 플레인 로그 양 확인은 클러스터가 있어야 하므로 다음 세션의 검증 항목으로 둔다.

## 7. 트레이드오프 / 다음 개선
- 계산 조건: 단가는 2026-09-28 발행 가격표의 온디맨드 정가다(크레딧·할인·세금 제외).
- 공인 IPv4 가운데 ALB 몫(약 3개)은 AZ 수만큼으로 가정했다.
- 노드 루트 볼륨은 gp2 단가 하나로 계산했다(타입은 확인 범위 밖). 둘의 차이는 노드당 약 $0.0006/h다(계산).
- 세션 대입(§4)은 "평시 5대 + 발생기 3대가 세션 내내"라는 가정이다. 실제로는 사전 확장(9대)·폭증 run 동안 더 들고, 발생기를 늦게 올린 세션은 덜 든다.

## 8. 배운 점 (면접 답변용 한 줄)
노드 1대를 줄이는 실험을 몇 차례 한 뒤 세션 비용을 항목별로 나눠 보니, 노드 1대는 세션 비용의 6%였다. 발생기(28%)와 Redis(19%), 그리고 세션 길이 자체가 더 컸다. 그래서 "무엇을 최적화할지"를 금액 비중으로 먼저 정하는 순서로 바꿨다.
